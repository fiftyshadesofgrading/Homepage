Most of us have a data set sitting in a folder somewhere: survey points, a list of sites, an export from a model. It does its job in the project and then just sits there. The gap between “a file on my machine” and “a page anyone can open” is smaller than it looks, and the fastest way to see that is to do it with something silly.

So here is every Waffle House in the country, colored by the current temperature at its location. Hover or tap a dot.

What you’re looking at

Blue is cold, red is warm, and the pale gray in the middle is 50°F (10°C), roughly the “grab a jacket” line. The deep south and the Carolinas hold most of the dots, which is exactly where the chain lives; check the state table if you want the exact counts.

The temperatures come from Open-Meteo, which serves weather model data free and without an API key. Nearby stores share one grid cell, so about 1,400 lookups cover all ~2,000 locations. That matches the model’s resolution anyway: this is a forecast model’s idea of the air temperature there, not a thermometer on the roof.

Put your own data set online: the four steps

Nothing here needs a framework, a build server, or a database. It is a folder of static files.

1. Start with a table that has coordinates

The locations come from a public CSV of Waffle House store data (alex-patton/wafflehouse_index, a snapshot from June 2026). The only columns this map needs are a store number, city, state, latitude, and longitude. Your survey points, utility structures, or project sites work the same way.

store_number,city,state,latitude,longitude
1791,SAINT JOSEPH,MO,39.72406,-94.79321
1388,BONNER SPRINGS,KS,39.09747,-94.88252

2. Project it once, ahead of time

A small Node script reads the CSV, converts each latitude/longitude into x/y on an Albers map of the US (the same projection family you know from state plane work), and writes the state outlines as plain SVG paths. The result is one JavaScript file with all the geometry baked in, so the page needs no map library and no tile server.

npm i us-atlas topojson-client d3-geo
node tools/make-map-data.mjs data/waffle-houses.csv map-data.js

3. Draw it with SVG and style it with CSS

Every location becomes a <circle>. The look (land color, dot outline, the toggle, the cards) lives in a stylesheet, so restyling it is a CSS edit, not a code change. A scripted nearest-dot lookup powers the hover tooltip so small dots stay easy to hit on a phone.

4. Attach the live part

The page asks Open-Meteo for the current temperature at each grid cell, in batches of 100 coordinates, then paints each dot. Results are cached in your browser for 15 minutes so reloading doesn’t hammer the service.

const url = `https://api.open-meteo.com/v1/forecast
  ?latitude=${lats}&longitude=${lons}
  &current=temperature_2m&temperature_unit=fahrenheit`;
const rows = await (await fetch(url)).json();   // one result per coordinate

That’s the whole pattern: table, projection, SVG, one API call. Swap the Waffle Houses for your own points and swap temperature for whatever you can look up by coordinate.
